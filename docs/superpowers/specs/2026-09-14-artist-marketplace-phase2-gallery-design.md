# Онлайн-галерея художников — Этап 2 (Галерея и личный кабинет художника)

## Обзор

Продолжение уже реализованного и задеплоенного Этапа 1 (авторизация,
роли, заявки продавцов — см.
`docs/superpowers/specs/2026-09-13-artist-marketplace-phase1-design.md`).
Этап 2 добавляет то, ради чего продавцы вообще регистрируются: загрузку
картин художником, их модерацию админом и публичную галерею, где
покупатели их видят.

Одна фотография на картину (без галереи снимков одной работы —
осознанное упрощение для MVP). Каждая картина — уникальный оригинал в
единственном экземпляре (модель без "остатков", уже зафиксирована в
Этапе 1). Категории и техники — справочники, которые ведёт админ через
интерфейс, а не фиксированный список в коде.

## Модель данных

**`categories`** — справочник категорий картин, управляется админом.
| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid, PK | |
| `name` | text, unique, not null | Например: "Живопись", "Графика" |
| `createdAt` | timestamp | |

**`techniques`** — справочник техник/материалов, управляется админом.
Структурно идентичен `categories`, но представляет отдельное понятие
(техника ≠ категория) и хранится отдельной таблицей — не общей
"таксономией" с дискриминатором, ради простоты и единообразия со стилем
схемы Этапа 1 (одна сущность — одна таблица).
| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid, PK | |
| `name` | text, unique, not null | Например: "Масло на холсте", "Акварель" |
| `createdAt` | timestamp | |

Удаление категорий/техник вне рамок Этапа 2 — только создание и
переименование существующих. Это осознанное упрощение: удаление
поднимает вопрос "что делать с картинами, которые на неё ссылаются", и
не обсуждалось как необходимое для MVP.

**`artworks`** — сами картины.
| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid, PK | |
| `sellerId` | uuid, FK → `users.id`, not null | Художник-владелец (`role = seller`) |
| `title` | text, not null | |
| `description` | text, not null | |
| `price` | integer, not null | Точная сумма в сомони (TJS), обязательна |
| `heightCm` | integer, not null | Высота, см |
| `widthCm` | integer, not null | Ширина, см |
| `categoryId` | uuid, FK → `categories.id`, not null | |
| `techniqueId` | uuid, FK → `techniques.id`, not null | |
| `imageUrl` | text, not null | Публичный URL файла в Vercel Blob |
| `status` | enum: `pending` \| `published` \| `rejected` \| `sold` | |
| `rejectionReason` | text, nullable | |
| `submittedAt` | timestamp, not null | |
| `reviewedAt` | timestamp, nullable | |
| `reviewedByAdminId` | uuid, FK → `users.id`, nullable | |

### Жизненный цикл статуса

Тот же паттерн, что и заявки продавцов в Этапе 1:

1. Художник создаёт картину → сразу `status = pending` (черновиков нет —
   форма сохранения сразу отправляет на модерацию, отдельной кнопки
   "отправить на проверку" не будет).
2. Админ на `/admin/artworks` одобряет → `published`, либо отклоняет
   (с причиной) → `rejected`.
3. Художник может отредактировать отклонённую **или уже опубликованную**
   картину — любое редактирование (включая правку цены/описания у уже
   опубликованной работы) возвращает статус в `pending` и требует
   повторного одобрения. Как и в Этапе 1, это должно быть update
   существующей строки (upsert-семантика на уровне бизнес-логики), а не
   создание новой записи.
4. Из `published` художник в любой момент может сам перевести картину в
   `sold` — единственный переход, не требующий модерации. Обратного пути
   (`sold → published`) в этом этапе нет.

## Личный кабинет художника

`/dashboard/seller` (сейчас заглушка из Этапа 1) становится реальной
страницей:
- Список своих картин с статусами (`на модерации` / `опубликована` /
  `отклонена` / `продана`), причина отказа показывается у отклонённых
  (как у статуса заявки продавца).
- Кнопка "Добавить картину" → форма: фото (один файл), название,
  описание, цена, высота, ширина, категория и техника (оба —
  выпадающие списки из справочников).
- У каждой карточки: "Редактировать" (открывает ту же форму,
  предзаполненную; сохранение — тот же upsert-путь, что и создание) и,
  только для `published`, кнопка "Отметить как продано".
- Доступ гейтится так же, как остальные seller-маршруты в Этапе 1: через
  `role = seller` в middleware, плюс собственная проверка на странице
  (defense in depth, тот же паттерн, что и `/admin/sellers`).

Загрузка фото — через серверный Server Action (форма → action → запись
в Vercel Blob + БД), не через прямую клиентскую загрузку. При одном
файле скромного размера на картину серверная загрузка проще и
согласуется с паттерном форм, уже использованным во всём Этапе 1.

## Админ: модерация картин и справочники

**`/admin/artworks`** — по образцу `/admin/sellers` из Этапа 1:
- Очередь картин со статусом `pending`.
- Одобрить / отклонить (с причиной при отказе).
- Собственная проверка `role = admin` на странице и в server actions
  (defense in depth), переиспользуя тот же паттерн, что и одобрение
  заявок продавцов.

**`/admin/categories`** и **`/admin/techniques`** — идентичные по
структуре страницы: список существующих значений + форма добавления
нового + переименование существующего. Без удаления (см. выше).

## Публичная галерея

**`/gallery`** — каталог картин со `status = published`:
- Сетка карточек: фото, название, цена, имя художника.
- Фильтры: категория, техника, диапазон цены (от/до).
- Сортировка по дате публикации, новые сверху (разумный дефолт, отдельно
  не уточнялся).
- Постраничная пагинация, 24 картины на страницу (разумный дефолт).

**`/gallery/artist/[id]`** — публичная страница художника: `displayName`
и `bio` из `seller_applications` (уже собраны в Этапе 1), Telegram-контакт,
список его картин со `status = published` (проданные показываются с
пометкой, не скрываются — см. ниже).

**`/gallery/artwork/[id]`** — страница одной картины: фото, название,
описание, цена, размеры, категория, техника, ссылка на страницу
художника. Если `status = sold` — страница остаётся доступной (не
404), но с явной пометкой "Продано" вместо кнопки покупки (которой пока
и так нет — корзина/заказы это Этап 3).

## Вне рамок Этапа 2

Корзина и оформление заказа (Этап 3), реальная оплата (Этап 4), чат
покупатель↔художник, несколько фото на одну картину, удаление
категорий/техник, отзывы/рейтинги, избранное — ничего из этого сюда не
входит.
